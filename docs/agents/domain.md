# Domain docs

Ceres 采用 single-context 的领域文档布局。

## 阅读规则

探索相关代码前：

- 若根目录已有 `GLOSSARY.md`，读取与当前任务有关的术语。
- 若根目录已有 `GLOSSARY-MAP.md`，按其中的指引读取相关上下文的词汇表。
- 若 `docs/adr/` 已存在，读取涉及当前改动的架构决策；有上下文专属 ADR 时一并读取。

上述文件或目录不存在时直接继续，不因缺失而提前创建词汇表、映射或 ADR。术语及决策实际得到确认后，再由 `domain-modeling` 等相关工作按需记录。

## 布局

- `GLOSSARY.md`：根目录领域词汇表。
- `docs/adr/`：架构决策记录。

现有前端、后端及同仓 Mercury 模块不需要仅为 skills 配置建立多上下文映射。

## 使用约定

- 问题标题、设计、测试和报告中的领域概念沿用词汇表的定义，不使用词汇表明确排除的同义词。
- 需要的概念尚未记录时，先核对现有代码和文档，判断是否有实际术语缺口；不自行发明新的领域概念。
- 提议与已有 ADR 冲突时，明确指出对应 ADR 和重新讨论的原因，不静默覆盖既有决定。
