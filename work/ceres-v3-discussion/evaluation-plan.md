# Ceres V3 评测准备

更新于 2026-10-06。产品依据为 [PROJECT-v3.md](../../PROJECT-v3.md) 中 Q1–Q23 已确认的决定。本文件是评测案例与记录模板初稿，未执行评测，不是已通过的证据；正式用例、业务数据和计时边界在实施规格中冻结。

## 评测对象与验收

分别检查 Kev 服务归属判断、完整切换与业务行为、业务完成后的 Prompt 改良。Kev 已选定，评测用于改进实现，不承担重新选型。固定核心用例全部通过、关键违规为零；性能按 Q20 检验，常规请求路由新增等待 P95 ≤1 秒，完整回复目标 ≤15 秒，冷启动单列。

采用模拟门店政策、模拟订单和隔离业务数据。一般政策依据以 [POLICIES](../../Mercury/mercury/seed.py) 为当前准备来源：P-RET-01 为签收后 7 天内、可退商品按件申请；P-RET-02 为不可退商品限制；P-DEL-01 为当天下单配送、实际送达以物流为准。正式采样须固定实际读取的政策版本，不能只引用这份准备说明或让旧聊天代替当前事实。

## 首批核心案例草案

以下是公开的开发与核心验收场景，不能再作为未知留出集证明泛化。A、B 代表隔离数据中同一匿名 owner 的不同订单，执行前固定状态与数据版本；尚未创建这些测试数据。

| ID | 输入与必要上下文 | 预期结果与可观察断言 |
| --- | --- | --- |
| R01 | 可可中说“想买两瓶无糖可乐” | 继续可可，沿用导购；无售后切换提示 |
| R02 | 可可选购时问“这个商品不喜欢能退吗”，未指向订单 | 继续可可；查政策、说明条件与来源，不认定某单资格，不提交申请 |
| R03 | 墨墨未选订单时问“一般签收后几天内能退” | 继续墨墨，先回答一般政策，不强制选单；涉及具体资格才需要订单 |
| R04 | 可可中明确指向订单 A，问“这单到哪了” | 建议墨墨；用户同意前角色不变，无订单操作 |
| R05 | 墨墨已选订单 A，问“这单还能退吗” | 继续墨墨；重新读取 A 的事实与政策，一般规则不冒充实际资格 |
| R06 | 可可刚讨论移除清单可乐，接着说“取消一下” | 继续可可，关联清单对象，不取消已下单订单 |
| R07 | 无可用对象上下文，只说“取消一下” | 原聊天澄清对象，不自行切换或执行取消 |
| R08 | 墨墨中表达新选购需求“想买无糖可乐” | 建议可可；需同意才切换 |
| R09 | 可可中问候或表达简单生活感受，未提出采购需求 | 继续可可，不自动新建购买任务 |
| R10 | 可可此前讨论订单，最新明确说“现在先帮我选无糖可乐” | 按新诉求继续可可，不被旧订单话题牵走 |
| H01 | 接受 R04 的切换建议 | 携原话、A 和必要相关对话；墨墨查询 A，不要求重输、不重复处理消息 |
| H02 | 拒绝 R04，随后再次问明确订单问题 | 留当前角色；本次打开不再自动弹出切换提示，固定入口可用，无越界操作 |
| H03 | 尚有明确未处理的订单诉求，主动点击墨墨入口 | 携该诉求续接，原有业务确认仍适用；不恢复自动提示次数 |
| H04 | 已处理完消息后单纯主动切换角色 | 恢复目标会话及业务进度，不重新发送已处理旧消息 |
| H05 | 可可与墨墨来回切换后，再结束本次打开并重新进入 | 来回切换不重置次数；新的打开周期才恢复自动提示额度 |
| H06 | 目标墨墨旧会话选的是 B，但本次交接明确指向 A | 本轮关联 A 并重新读取，不静默沿用 B 的状态或资格结论 |
| F01 | 注入 Kev 调用不可用，用户提出当前角色业务或跨服务诉求 | 提示自动路由不可用；仅处理自身业务、手动入口可用；本轮记录路由失败 |
| P01 | 可可问一般配送时间，未指向订单 | 回答模拟配送政策并注明实际送达以物流为准，不编造某单预计到达时间 |

探索案例另记：“退掉这单，再买另一种可乐”。申请提交成功才允许继续采购；失败暂停、说明原因并询问，继续采购也保留失败状态。成功不代表退款到账，也不授权自动返回可可。探索结果不计入核心完成率。

## 构建与使用案例

按业务场景分组，补充改写、上下文不足和上下文反转。相同原话配不同上下文应分别标注，近似改写不能跨开发集和独立留出集。先用开发集改进输入与判据，再固定版本检查留出集；修复案例进入回归集，不冒充从未见过的输入。

每条案例先记录当前角色、对象与状态、相关对话、逐轮原话、预期结果、禁止行为及依据。含义尚未达成共识的输入先标为待定，不计入正确率。政策答案按条件和来源核对，不要求逐字匹配；业务动作按状态核对，不能只看回复中是否出现关键词。初版以业务断言和人工复核为主。

## 单次执行记录模板

| 字段 | 填写内容 |
| --- | --- |
| run_id / case_id / scenario_group / split | 执行标识、案例 ID、业务组、开发／回归／留出或故障注入 |
| evidence_kind / status | 受控行为验证／真实模型采样／页面验证；待执行／通过／失败／阻塞，不能用模板默认值声称通过 |
| source_version | Git commit，以及未提交源码的冻结路径与摘要 |
| data_version / case_version | 隔离订单、政策、供给及用例版本；按该用例需要记录 |
| model_version / prompt_version | 实际 Kev、基础模型、角色主模型、判据与 Prompt 版本；记录运行参数与 GPU 绑定 |
| input / context / initial_state | 逐轮原话、实际提供的相关上下文、角色／对象／业务状态及本次打开的提示记录 |
| expected / forbidden / label_basis | 预期路由、业务动作、禁止结果和标注依据 |
| actual | Kev 选项与概率、应用最终决定、回复、动作与最终业务状态；故障保留原始错误 |
| checks / review | 每项断言结果、失败原因、人工复核结果与待定项 |
| timing / size | 路由新增阶段耗时、完整回复耗时、冷启动标记与样本量；实际发送的 Prompt 长度及可获取的 token 用量 |
| artifacts | 原始响应、trace、状态快照或页面证据路径；未生成的证据留空并说明 |

单例结果可以写入执行目录的 JSONL；这张表仅定义记录内容，不要求新增通用评测框架。

## 统计与版本比较

先分角色与场景报告正确数／总数，再报告三类结果的混淆情况。误切换率的分母是预期不应建议切换的案例，分子是错误建议切换的案例；漏切换率的分母是明确需要跨角色承接的案例，分子是未建议切换的案例。澄清类同时检查漏澄清与不必要追问，不能靠始终留在当前角色取得好结果。

正常输入中发生的模型调用失败作为失败保留在总数中，另报服务失败数；故障注入用例单列，正确降级不等于成功路由。关键违规单独列举，不被总体正确率掩盖。样本较小时给出原始计数，不将百分比推广到所有中文表达。

性能保留逐轮原始耗时与样本量，按冻结的计时边界计算常规请求路由 P95，并逐例检查完整回复的 15 秒目标。冷启动、失败、超时单列，不靠排除失败宣称达标。路由新增等待按实际新增阶段计时，不要求主模型对照试验。

业务完成后固定未精简的 V3 基线、用例与业务数据，再改变明确的 Prompt 优化变量。比较关键业务断言、政策条件与来源、完整回复及路由耗时、实际 Prompt 长度；可获取 token 用量时一并记录。关键行为不能退步，缩短文字本身不算业务质量提高。真实模型、受控测试与页面结果分别呈现。
