# Ceres 下一阶段 Agent 体验拆票草案

来源：[实施规格](../../docs/plans/ceres-next-agent-experience-spec.md)。本草案待确认测试接缝、粒度和阻塞边；票据尚未发布到 tasks，不表示已开始实施。

## 测试接缝

主接缝：现有公开聊天 API 的多轮会话旅程，贯通回合、确认加购、角色交接和可查询业务结果；气泡与专题入口补真实前端点击验证。复用现有评测与 Trace，仅补新行为的断言和记录。

## 票据与技术依赖

| 票据 | 独立交付行为 | 阻塞依赖 |
| --- | --- | --- |
| [01 零食分类气泡到确认加购](ticket-drafts/ceres-next-agent-experience-01-snack-choice.md) | 用户说“来点零食”后选择供给支持的细类，再选具体商品并确认加购；点选与文字回答都保留已明确条件。 | 无 |
| [02 饮品与多候选分类筛选](ticket-drafts/ceres-next-agent-experience-02-drink-candidate-choice.md) | 饮品需求和跨类型候选通过分类气泡收窄；同类多个商品直接展示，并按有依据的口味、品牌或规格选择继续。 | 01 |
| [03 内部能力路由与 workflow 直达](ticket-drafts/ceres-next-agent-experience-03-capability-routing.md) | 可可把品类探索、采购与修改、事实问答、闲聊交给对应能力；有效结构化输入和齐全参数直接由 workflow 完成，复杂表达仍被主模型正确理解。 | 01 |
| [04 两角色 Prompt 模块化](ticket-drafts/ceres-next-agent-experience-04-prompt-modules.md) | 同样的选购、咨询、闲聊与售后输入继续得到正确结果，各角色及能力只使用必要的表达、规则与事实，并能复核实际发送的 Prompt。 | 03 |
| [05 逐模块精简与固定对照](ticket-drafts/ceres-next-agent-experience-05-prompt-refinement.md) | 用户在相同任务下得到符合验收的简短回复，Prompt 精简的正确性和实际开销变化都有可复核前后记录。 | 04 |
| [06 售后后继续采购与自然回复](ticket-drafts/ceres-next-agent-experience-06-after-sales-resume.md) | 用户购买并模拟结算后，在墨墨提交售后申请，再选择回可可选购替代商品；已明确诉求不用重输，状态与下一步用自然中文说明。 | 04 |
| [07 主页专题到限定成品选购](ticket-drafts/ceres-next-agent-experience-07-themed-products.md) | 主页现有卡片直接打开可可，展示简短专题介绍与对应限定成品；选择活动商品后沿现有清单/确认加购完成选购。 | 01 |

技术依赖仅表达本方案需要复用的契约、分支或冻结结果。06 依赖 04 的表达组织与其上游选择契约；07 依赖 01 的共用选择承接。02、05 对后续独立票的推荐先行次序，不额外伪造为技术阻塞。

## 推进和修改归属

按用户已确认次序优先推进 01→02→03→04→05→06→07→08；每票同步形成用例和记录。技术阻塞发生时，可推进依赖已满足的独立票。05 与 06 的 Prompt 变更按实际修改范围串行登记，保持单变量对照；共享选项、商品/供给与索引由主会话协调归属。

必要时允许补充支撑已确认场景的最小模拟商品及供给，并记录数据/索引版本；不把数据扩充效果归因于路由或 Prompt。所有票据的业务、模型、前端和人工证据分别保留。

## 发布后的本地 tracker

批准后沿项目约定发布一份总 TASK 及八份单票，文件名与本目录草案一致；规格沿用已有唯一文档。各票初始状态为待开始，依赖完成后才可进入实施；执行完并不自动写已验收。

当前用户授权为整理规格与拆票。本轮不实施业务、不导入商品、不修改旧任务、PROJECT 或 PRD。
