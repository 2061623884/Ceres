# 06 有效审查修复

Spec 对第一对真实 R02 输出发现：候选在只有 P-RET-01/P-RET-02 两条来源时追加“审核结果为准”，来源未提供审核要求。原对照退出0只表示HTTP脚本完成，不表示语义质量通过；该候选质量判为失败。保留原请求、响应、usage和退出码，不回写。

按这个实测错误在实际调用的短政策角色 Prompt 中补充“不添加来源未提到的审核流程、商家要求、条件或时限”，不新增业务、校验器或平台。专职 Agent 在相同固定请求上复核新候选；只改变 system 变量，TDD有效失败为已保留真实输出的来源条件偏差，未编写镜像这句文本的断言。

v2 原始候选仍出现“不能代表已审核通过”的来源外流程状态词，Spec 保留有效发现；虽是免责声明，未据此声称已通过。v3 只将新短角色规则进一步限定为“规则与来源＋资格信息不足”，明确不描述来源外页面、申请流程或进度，保留政策事实、模拟边界、协议及不执行业务的要求。v2 fresh baseline 本身也提到未来源支持的页面位置，记录其质量偏差，不能把固定请求重发称成确定重放或假定 baseline 必然正确。
