# 06 实施接续边界

05 功能基线与双轴已交付，06 从 TASK 接续；同版 Q20 仍留待 07。此处沿用已确认的公共 API 与外部模型请求测试边界。

沿用已确认的公共导购回合 API 与真实 provider 的外部模型请求边界。已有 `test_keke_policy_answer_uses_conditions_instead_of_product_recommendation` 从公共 API 发一般配送问题，实际经过理解、政策检索、答复两阶段；它可以观察真实发送的 Prompt、回复协议、政策来源和无采购行为。

拟实施一个切片：理解阶段保持原 Prompt；只有全部 query_results 都为一般政策的答复阶段，使用简短的导购角色与事实、协议约束，加现有 POLICY_COMPLETE_PROMPT，省去该阶段不执行的选购、菜谱、编辑和历史采购规则。混合结果、购物与历史流程保持现有组合入口。先在已有公共 API 测试中增加政策答复 system 不超过 2000 字符、理解 system 保持原文及来源/协议断言，由专职测试 Agent 记录有效 red，再最小实现、定向 green。

比较固定 05 功能基线的实际政策请求与候选请求：只有 system 文本变化；模型配置名、输出预算 3072、温度、其余 messages、模拟政策和 JSON 格式保持一致。专职 Agent 记录实际发送及原始响应、usage、字符长度、耗时与正确性，主会话人工核对模拟门店、适用条件、来源及没有订单资格/申请承诺。远端权重 revision 不可验证的限制保留。

模型请求重放比较与完整 API 时延分开，不将重放冒充页面等待或完整回合性能。必要回归、独立 Standards/Spec 审查和修复完成后提交本票；07 最终同版验证仍检验 Q20。
