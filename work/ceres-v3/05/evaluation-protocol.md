# V3 固定评测执行约定

用例在采样前冻结于 `evals/v3/core-cases.json`。18 个公开案例是开发/回归，按公共 API/SSE 与实际业务状态验证；用例文件本身没有通过结果。每个案例必须链接实际 pytest 节点和原始命令。R04 的未同意边界、H01 的原话交接、H06 的订单 A/B 可以由同一完整旅程分别检查，不把一个断言复制成三份测评。

`test_v3_core_evaluation.py` 补齐固定原话的 R01/R08 可乐清单与数量，以及 R02、R03、R05、R09、P01 的路由与业务联通，其他案例对应 03/04 旅程。受控模型只替换外部模型边界，实际服务、owner 校验、政策表、订单资格、状态与回执均运行。

真实采样分两组，均由专职测试 Agent 执行：

- `test_v3_live_routing.py`：预声明两轮共 22 次公开路由输入；实际 API 准备上下文、调用固定 Kev，角色/记忆模型受控。保存实际模型输入、原始 choice/概率、生产 route_ms、终端 SSE 和所有失败。第二轮是性能样本，不是失败重试。
- `test_v3_live_sampling.py`：修正版 5 条公开真实 Kev + 真实角色主模型 API 采样，包含核心 R01 的两瓶无糖可乐及单独的具名鸡蛋变体；保存实际发送 Prompt、模型响应、业务状态与后台 API 完整回复时长。使用实际测试库配对的现有 lexical 索引，不声称本机 hybrid 供给已验证。背景记忆只返回空结果，真实 worker 完整收尾；这不冒充记忆模型质量验证。捕获器覆盖 Ceres httpx 与 OpenAI 的公开 DefaultHttpxClient 发送边界，不记录凭据，缓存上游流以保存原始响应，不声称首 token 或页面呈现时延。

路由 P95 使用生产 `route_ms`，nearest-rank：排序后第 `ceil(.95*n)` 项；报告样本数、失败数、误/漏切换及澄清错误。失败保留，不能剔除后宣称达标。后台完整回复从本地公共 API 请求到终端 SSE 完全读取计时（含调用开销），页面等待另列；转接确认请求单列，不把等待用户选择的时间算成模型推理。加载冷启动以 01 原始记录为准，客户端初始化及首请求另列，不拿已加载模型调用伪装冷启动。

模拟数据由现有 `conftest.py` 的实际 seed 入口重建；测试文件选择的 source fixture 必须记录。新增真实/核心文件用 `support.v2_fixture` 的不存在源路径，避免读取本机可变目录。继承测试若使用本机源库，要冻结其摘要与实际数据；不得把两种供给称为同一数据。订单由本人购物车公共 API 创建，实际 ID/时间在每条记录保存，`fixture:A` 不发给生产模型当作真实订单。

独立检查冻结于 `evals/v3/holdout-cases.json`，按新的对话现象分组（否定旧意图、引用文本、回答对象澄清、同句自纠），不是公开句子的近似改写。业务标签共用；仅 4 条，不作统计泛化结论。改良者使用公开开发案例，候选冻结后才执行留出；若根据留出失败调整，该候选后续结果不能仍称首次独立通过。

每次执行保存 git HEAD 与未提交完整源码 ZIP 摘要、适用供给/政策/订单、模型 revision、实际 Prompt/准则、执行命令、解释器、环境（凭据只记存在性）、退出码和运行前后源码摘要。主会话读取原始记录后维护 TASK；性能不足不伪造成功，也不阻断已完成业务基线进入 06。真实功能失败必须先修复。

Kev 的本地权重、基础模型与服务源码使用 01 的固定 revision 和校验记录。角色主模型使用远端 API 的配置名 `qwen3.8-27b`，保存实际请求名和响应模型字段；该提供方未向本项目提供可校验权重 revision，不能宣称远端权重不可变。06 对照固定同一 API、配置名、参数和原始业务输入，并保留这一版本限制。

真实路由组通过公共 API 构造上下文，原始 outbound state 是实际测量输入。R02 使用可乐商品页，未补造此前的比较对话；R06 用真实 Guide 对话保存清单移除话题，不声称已存在可移除的清单；R08 指定真实 owned order，未补造“刚查询状态”的回合。它们验证对应服务边界，不冒充用例文件示意 state 的逐字重放。业务清单、政策依据和交接状态由受控公共 API 核心旅程另作断言。

## 修正版与原版的界线

原版 22 路由及 4 角色样本、失败断言与捕获缺口全部保留。修正版 R06 的受控角色问句明确询问移除采购清单，不更改原话、标签或 Kev 准则；R02 角色采样补齐原固定案例的商品页。鸡蛋变体原话没有指定包装枚数，旧断言只允许 6 枚装不符合该原话；修正版允许冻结供给中原有的两种鲜鸡蛋包装之一、数量 1，并重新读取商品事实。这个断言纠正不追写原版为通过。核心 R01 的两瓶无糖可乐另行实测，不用变体替代。

原版角色回执的 sidecar 摘要按写入前的 LF 文本计算，Windows 写入后产生 CRLF；实际字节不匹配问题及 LF 规范化匹配分别记录于主会话审计。修正版用 write_bytes，摘要对应实际文件字节。不同版本结果不拼接为同版全通过。

v3 修正与依据见 [fixes.md](fixes.md)：准则明确区分服务职责和业务内部澄清；初始采购件数与手动改行覆盖字段分别解释；采样异常持久化并重抛。真实采样使用已记录的 OpenAI 3.19.2 / httpx 0.28.1 / SDK httpx2 2.13.1；该捕获配置不要求普通测试收集使用新 SDK，也不宣称其他版本测量已验证。候选再次冻结后由专职 Agent 执行，原 v1/v2 的失败不改写。

v4 基于 v3 R01 的 `finish_reason=length`、1536 completion tokens 全为 reasoning、无业务 JSON，调整现有运行配置 `LLM_MAX_OUTPUT_TOKENS=1536→3072`。不改模型、主 Prompt、调用流程或加入重试；新预算单独验证业务输出及等待，不预先保证成功或达标。`.env` 不归档、不提交，只保存非凭据运行配置。角色回复 Q20 必须有五个指定案例、H01 独立确认回合共六个计时且断言全过；样本缺失或失败不能当通过。

v5 更正 R01 的首轮验收步骤。独立 Spec 核对确认：冻结路由案例只要求可可继续；既有 V2 可乐规则要求先比较、不自动选款，用户选实际商品后才准备清单。v4 已返回完整 JSON 与真实商品卡，首轮 plan=null 合乎该流程；原采样失败记录不追写。新版保留原首轮原话和路由标签，要求只读、无自动清单与无加购；再由用户明确选择首轮实际展示的无糖可乐卡片、两瓶，独立记录第二回合及其路由、清单 SKU/件数/当前报价库存。该多轮旅程不冒充原单轮采购成功，不改变 V2 规则或生产 Prompt。Q20 在五份完整角色回执中同时要求 R01 选择及 H01 确认，共七个实际 API 计时；缺任一回合不能通过。
