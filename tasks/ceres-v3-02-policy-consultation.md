# 02 两角色共享一般政策问答

状态：待开始
负责人：主 Agent
规格：[V3 实施规格](../docs/plans/ceres-v3-spec.md)
依赖：无；继承 V2 身份、数据库与订单能力，与 01 下载/加载独立。

## 交付行为

可可购物中能回答有条件与来源的一般政策，墨墨未选订单也能咨询政策；具体订单资格与售后操作仍需选单，普通问答不修改订单。

## 验收标准

- [ ] 可可先于墨墨创建会话问政策也能读取同一模拟事实源，初始化不覆盖已有政策；答案保留 policy_id/标题与条件。
- [ ] R02、R03、P01 的聊天 API 受控结果满足约定：不因一般政策强制选单，不冒充订单资格，不产生申请。
- [ ] 墨墨未选单的咨询工具范围仅涵盖政策读取／一般回答，显式订单操作不能通过该入口执行；已有选单与 owner 隔离回归通过。
- [ ] 问候不自动创建采购任务；明确吃饭/采购诉求进入既有导购，持续离题时说明服务范围。
- [ ] 对检索不命中或不足的结果如实说明；只针对实际失败案例优化检索，不新增商品百科或无调用方的知识框架。
- [ ] 公共接口红/绿、必要回归、最小 demo 输入输出与 Standards/Spec 审查证据完整；正式 UI 另记。

## 测试边界

两角色聊天 API/SSE 与隔离政策表、订单状态；既有政策测试和订单/owner API 是先例。模型边界注入可复核工具调用，真实角色采样留 05，前端生产代码交 Cursor。

## 阻塞与下一步

无外部模型依赖，可在当前准备完成后开始。先记录本票源码基线，建立共用政策读取和无选单边界的公共接口失败用例，再实现最小闭环。当前未改生产 Prompt、查询协议或检索代码。
