# 零食品类选购限定闭环

更新于 2026-10-04。状态：**待验收**。负责人／主会话：当前 Ceres 产品讨论与实现会话，由本会话 Codex 维护。

## 授权与范围

用户批准少量具有明确模拟门店供给的零食入库，完成“品类需求 → 展示匹配商品 → 用户选择 → 生成清单 → 明确确认后加购”；只补本例最少商品与 Offer。无匹配如实说明，不推荐其他品类。固定案例独立重复两次，更新本 TASK 与 PROJECT。

本任务承接 [超时案例修复](../work/model-timeout-case/IMPLEMENTATION.md)。[旧商品扩充任务](catalog-expansion.md)的 11 SKU 交付和待验收状态保持原约定；[语义任务](semantic-contract.md)的历史停止与验收缺口不自动恢复。

## 限定验收结果

- 已补原味薯片70克袋装、苏打饼干100克盒装两项 approved/demo SKU，各有 store-demo-01 可售 Offer、明确包装、价格与库存；旧商品、旧 Offer、菜谱、schema 未改。14 项供给／索引核对通过，重复导入新增数为 0。
- “来点零食”只展示实际匹配零食候选；选择前无清单与加购。两次真实模型/API 固定回放均选展示第一项苏打饼干：一盒 ¥6.90，确认前购物车为空，点击确认后只增加该 SKU 一盒。
- 普通“好的”保留清单、等待明确确认，不宣称已确认／已加购，不写购物车。
- 固定“来点冰淇淋”在待确认清单及已加购后都返回未匹配，不推荐其他品类，清单和购物车逐项不变。
- 相同源码、供给、索引及配置模型，独立新 owner／会话完整重复两次通过。两次首轮分别 6.855／7.532 秒，选购轮 3.054／3.136 秒。该结果不代表所有模型采样都通过。
- 相关离线回归 80 通过、1 跳过；新用例同时覆盖改变展示顺序后的第一／第二项选择、有效 ACK、待确认和非空购物车状态的无匹配保留。跳过项为既有烘焙清单测试（`baking plan not ready`），不是本轮新增用例。
- 页面最终核对了两款候选、苏打饼干清单、确认前空购物车、明确点击确认及确认后一盒 ¥6.90；选择中曾遇到上游超时，手动新发选择后完成。页面证据属于恢复后的验证，不写成无中断重复两次。

## 仍有的边界

本例按本次授权展示两项候选，尚不证明 PROJECT 中单款主推与推荐理由、其他品类、饮品偏好、所有零食 SKU 的真实模型加购或完整筛选比较通过。薯片的选择与价格确认由离线回归覆盖；真实模型两次正向加购均为苏打饼干。

调试过程中三次约 45 秒的上游模型读取超时及 ACK 措辞／EMPTY_PROPOSAL 失败均保留，未计为通过。最终两次 API 回放通过不能证明响应已长期稳定；持续响应可靠性和速度门槛仍是 PROJECT 第一优先项。本轮未增加重试、兜底或异常吞错。

检索索引为 321 SKU、426 文档、0 向量；实际检索使用现有词法路径，健康检查仍报告 `VECTOR_INDEX_MISSING`。不作为完整向量检索交付。
