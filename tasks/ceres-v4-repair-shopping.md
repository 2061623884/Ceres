## 已观察的最小复现

R01：从「来点零食」选择薯片，回复称可查看商品卡片，但实际商品卡片为空且没有待澄清选项；未执行后续购买/确认。R07：明确无糖可乐采购要求后缺少采购清单。R11：明确修改预算后实际预算字段未达到要求。H04：先确认、追加数量，再确认追加部分返回 HTTP 409；该失败记录没有完整错误响应体，不能推断应用层错误码或根因。

上述属于可观察失败现象，尚未完成根因诊断。每个 execution 的完整输入、前后状态、调用、检查和跳过步骤见 run-03 对应目录；首批来源指向 run-01 的实际执行目录。`badcases.json` 含每次独立复跑的完整 argv，须使用新的输出目录，原记录不可覆盖；本轮不自动复跑。

有效 [UI run-02](../work/ceres-v4-evaluation/ui/run-02/result.json) 的零食旅程：分类气泡已显示并点击，明确请求「原味薯片70克两包，预算20元，整理成清单…暂不加购」后，实际完成回执报 `TARGET_NAME_MISMATCH`，说明目标「原味薯片70克」与引用「原味薯片70克袋装」不一致，本次未执行；plan=null、购物车为空。拦截保护了业务状态，但该选购目标没有完成。不得把这次失败归为旧 UI parser 问题，或仅改脚本输入绕过产品现象。
