## 交付行为

固定版本的完整路由、切换、政策和闲聊业务可复核，真实模型与性能均有原始记录，并冻结业务已完成、尚未精简的 V3 基线供后续比较。

## 验收标准

- [ ] 18 个固定核心业务场景及其关键断言全部通过；未经同意切换、错用订单、重复处理、重复提示和无来源政策等关键违规为零。
- [ ] 固定实际源码与未提交变动、模拟业务数据、模型/Prompt/准则、执行用例及接口版本；隔离数据可重建，不引用旧版本通过作为本版结论。
- [ ] 建立开发/回归/留出分组，公开核心案例不冒充留出；同一场景改写不跨开发与独立验证集，预期依据明确。
- [ ] 单列受控 API、真实 Kev 与角色主模型采样，记录路由准确情况、误切换/漏切换/澄清、业务结果和原始错误。
- [ ] 按规格记录路由新增阶段与完整回复逐轮耗时、样本量、P95 与冷启动；未满足 Q20 时明确保留失败，不将该性能项勾为通过。
- [ ] 冻结精简前业务基线、记录必要回归与双轴审查；功能失败不得移交为“业务已完成”，性能不足可以如实移交 06 优化。

## 测试边界

核心业务公共 API/SSE 与隔离数据上的完整旅程、真实服务调用及最小 demo；不以静态 demo 替代真实采样，不以 API 通过替代本人正式页面验收。
