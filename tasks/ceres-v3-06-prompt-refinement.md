# 06 Prompt 改良与固定案例比较

状态：待开始
负责人：主 Agent
规格：[V3 实施规格](../docs/plans/ceres-v3-spec.md)
依赖：[05 核心集成与精简前基线](ceres-v3-05-baseline-evaluation.md)。必须有功能通过的冻结基线，性能不足可作为本票优化输入。

## 交付行为

在业务已完成的 V3 上整理与精简实际调用的 Prompt，减少业务无关冗余，同时保留协议、角色边界、政策依据和确认要求；用固定案例给出比较记录。

## 验收标准

- [ ] 按现有组合入口整理实际使用的公共规则与角色片段，不建设未知用途 Prompt 平台或无调用方模块。
- [ ] 固定 05 基线、用例、业务数据与模型，仅改变记录在案的优化变量；保存实际发送的 Prompt 与版本。
- [ ] 固定核心关键业务行为全部无退步，政策条件与来源保持正确；不删除协议约束换取文字缩短。
- [ ] 比较正确性、回答依据、Prompt 长度及耗时，可获取 token 用量时记录；错误和性能未改善如实报告。
- [ ] 真实模型比较、必要行为回归、Standards/Spec 审查及有效修复完成；不因 Kev 已选定而伪造质量或速度通过。

## 测试边界

与 05 同一公共接口和业务状态断言，单列真实模型采样与人工解释质量复核。优化者使用开发集，冻结改良版后才作独立留出检查，避免按留出结果反复调参再称独立验证。

## 阻塞与下一步

没有 05 基线，本票不可提前精简生产 Prompt。完成依赖后针对记录的冗余或失败作最小改良，比较并修复有效问题，移交同版候选给 07。

## 证据

冻结 Prompt、原始输入/输出、对照结果、必要回归与审查进入 `work/ceres-v3/06/`；当前未执行改良或采样。
